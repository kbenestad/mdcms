# Unreleased changes

Changes merged into `development` that have not yet been released to `main`.

---

- Re-released v0.6.13 as v0.7.0 — it shipped new features (`mdcms bundle`, theme-file versioning, etc.) and per the newly-documented semver policy in `CLAUDE.md` (major = breaking, minor = features, patch = fixes), a feature release must bump the minor version, not the patch version. No functional changes beyond the version number itself.
- Fixed `docs/banner/v0.6.12.txt` still claiming to be "the latest version" after v0.6.13 shipped. Root cause: the release workflow's "mark the old version outdated" step compared `mdcms.py`'s `CLI_VERSION` before/after the version bump on `main`, but that bump normally already happened in the commit that merged to `main` (per `CLAUDE.md`'s versioning rule), so old/new compared equal and the flip silently no-opped. Replaced with a self-healing scan of all `docs/banner/v*.txt` files that flips any stale "latest version" banner other than the one just released.
- Documented the `docs/banner/vX.Y.Z.txt` version-status-banner mechanism and the X.Y.Z semver policy in `CLAUDE.md` — neither was written down before.
- `mdcms build` now trims a site's `assets/icons/` to only the icons actually referenced, and downloads any missing ones automatically. `CORE_ICONS` (rendered unconditionally by `index.html` — theme toggle, hamburger, search, pagination arrows, panel toggles, default callout icons) are always kept; `OPTIONAL_ICONS` (alternate `nav-section-expand-icon`/`-collapse-icon` choices, `language`, plus `categories-selecticon`/theme.yml callout `icon:` overrides) are only downloaded when a site's `config.yml`/`theme.yml` names them, and removed otherwise. Custom icon files (names outside the known stock set) are always left alone. Fixed as a side effect: `hearth-and-bean`'s panel-toggle icons had been missing from its `assets/icons/` and are now restored on build. Previously the renderer unconditionally preloaded all 29 stock icons regardless of whether a site used them, including 7 (`mobile_arrow_down`, `language`, `exclamation`, `dangerous`, `report`, `history`, `text_compare`) that were never wired to any code path or config key — those 7 are now either dropped entirely (6, truly dead) or downloaded on demand (`language`, usable via `categories-selecticon`).
- `mdcms delete` now accepts multiple site names in one call and a `-y`/`--yes` flag to skip the confirmation prompt, e.g. `mdcms delete apps dow k -y`.
