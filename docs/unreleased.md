# Unreleased changes

Changes merged into `development` that have not yet been released to `main`.

---

- **Fixed:** `mdcms register` failed with `Error: Download failed: HTTP Error 404: Not Found` for every new site. The starter template's manifest (`app/mdcms.json`) had gone stale: it still listed the six icons dropped when the stock pack was trimmed (`dangerous`, `exclamation`, `history`, `mobile_arrow_down`, `report`, `text_compare`) and was missing the four panel icons added since, so the download died on the first icon that no longer exists. The manifest is regenerated from the real `app/` tree, and the release workflow now regenerates it on every release so it cannot drift again.
- **Fixed:** a single missing file no longer aborts a template download. `register` now skips any manifest entry that 404s, warns which files were skipped, and finishes the site — only `index.html` and `config.yml` are still fatal. Network errors and other HTTP statuses fail the download as before.
- `mdcms upgrade` now handles dpkg-managed `.deb` installs itself instead of just printing manual instructions: it downloads the new `.deb` for the platform and installs it via `dpkg -i` (re-execing under `sudo` when not already root), keeping the package database in sync with the file on disk.
- `mdcms update`'s "Could not find a CURRENT VERSION banner" warning (shown for pre-0.6.6 legacy-marker sites) now names the exact `config.yml` path to edit and shows the banner line to add, instead of a bare "update it by hand."
- **Fixed:** `mdcms build` could write a `nav.yml` that no YAML parser can read. Page titles and section names were emitted with only minimal quoting, so a title containing a backslash (`C:\Users\me`) produced an invalid escape sequence, and one starting with a YAML indicator (`[2026] Roadmap`, `- dash lead`) parsed back as a list. The renderer then failed to load the nav at all, and the next `mdcms config` silently discarded the file. Values are now emitted as properly escaped YAML scalars, quoted whenever a bare scalar would not round-trip as the same string.
- **Fixed:** `mdcms config` silently wiped `nav.yml` when it could not be parsed. The section editors read the file, treated a parse error as "no sections yet", and wrote back only what they had just added — deleting every existing section and page entry with no warning. They now refuse to save and explain how to recover; the `mdcms config` summary reports the nav as unreadable instead of showing `sections: 0`.
- **Fixed:** a page's `sort:` was ignored on rebuild once the page was already in `nav.yml`. `mdcms build` preferred the value already written there, so changing the sort — by hand or through `mdcms config` → Manage pages — never moved the page in the nav. Frontmatter now wins, as `docs/reference-nav.md` has always documented; `nav.yml`'s value remains a fallback for pages that declare no `sort:` at all.
- **Fixed:** `mdcms build`'s "could not parse nav.yml; starting fresh" warning now spells out that section metadata (`defaultname`, `sort`, `parent`, `parent-sort`, `pagesvisibility`, `categorynames`, `pagination`) is lost when it restarts.
- **Fixed:** writing a structured block to `config.yml` (`default-category`, `categories`) left the file without a trailing newline.
